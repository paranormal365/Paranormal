### 2 — Browser auto-launch on start-full-stack

Updated `scripts/start-webapp-with-api.sh` to open the browser once the WebApp responds.

**Approach:** Before the `exec dotnet run` line, a background subshell is spawned that polls `http://localhost:5078` every second (up to 60 s) and calls `open` on the first successful response. The orphaned subshell survives the `exec` replacement; `exec` continues to run the dotnet process and stream its output to the task terminal (problem matcher unchanged).

### 3 — CMS Feature: Requirements Clarification

Gathered answers to 10 design questions before implementation:

| Decision | Choice |
|---|---|
| PageHtml vs sections | Keep `PageHtml` as summary; sections are additional blocks below it |
| Section types | RichText, ImageBanner, FileGallery, ContactInfo, MemberRoster, CustomHtml |
| Page hierarchy | Unlimited depth — recursive `ParentPageId` self-reference |
| Member groups | Both formal `OrgMemberGroup` entity AND individual member grants |
| Org logo storage | Dedicated `OrganizationLogo` entity |
| CMS security granularity | Add `CmsSection=27` and `OrgMemberGroup=28` to `OrganizationSecurityTable` |
| IsPublished | Keep as-is; add separate `IsPublic` (member-only vs public) |
| Preview mode | Both inline preview panel and full-page preview route |
| Coming Soon page | Pure UI fallback — no DB row until first page created |
| Implementation start | Data model + migrations first |

|---|---|
| `CmsSectionType` | `RichText=1`, `ImageBanner=2`, `FileGallery=3`, `ContactInfo=4`, `MemberRoster=5`, `CustomHtml=6` |
| `CmsPageAction` | `[Flags]` — `None=0`, `View=1`, `Edit=2`, `Delete=4` |

`OrganizationSecurityTable` extended in both `Ben.Data.Common` and `Ben.Service.Security`:
- `CmsSection = 27` / `26`
- `OrgMemberGroup = 28` / `27`

**New entities:**

| Entity | Key design |
|---|---|
| `OrganizationLogo` | FK → `UploadFile` (NoAction), FK → `Organization` (Cascade), `IsActive` flag |
| `CmsSection` | `SectionType` enum, `ContentJson` (nvarchar(max)), `SortOrder`, `IsActive`; FK → `OrganizationPage` (Cascade) |
| `OrgMemberGroup` | `Name`, `Description?`, `IsActive`; FK → `Organization` (Cascade) |
| `OrgMemberGroupMembership` | Junction: `OrgMemberGroup` (Cascade) + `OrganizationUserMembership` (NoAction to break cascade cycle); unique index |
| `CmsPagePermission` | `CmsPageAction` bitmask; nullable `AppUserId` OR `OrgMemberGroupId`; FK → `OrganizationPage` (Cascade) |

**Modified existing entities:**
- `OrganizationPage` — added `IsPublic` (bool), `ParentPageId` (Guid? self-ref), nav props: `ParentPage`, `ChildPages`, `CmsSections`, `PagePermissions`
- `Organization` — added nav props: `OrganizationLogos`, `MemberGroups`

**Cascade cycle fix:** `OrgMemberGroupMembership.OrganizationUserMembershipId` set to `NoAction` because both `OrgMemberGroup` → `Organization` and `OrganizationUserMembership` → `Organization` are cascades; SQL Server rejects two cascade paths to the same table.

### 6 — CMS UI (`Ben.Web.Library/Organization/Cms/`)

**`OrganizationList.razor`** updated: Actions column widened to 240 px; flat "CMS" button (Info colour) added as first action in each row → navigates to `/organizations/{id}/cms`. Not gated on CanEdit — users with any org permission can access the CMS editor; the API enforces security.

**New Blazor components:**

#### `OrgCmsEditor.razor` — `/organizations/{OrgId}/cms`
Main CMS hub page for an organization.

- `TelerikTabStrip` with **Pages** and **Logos** tabs
- **Pages tab:** `TelerikGrid` showing page list with Status badge (Published/Draft), Visibility (Public/Members only), section count, and per-row Edit / Sections / Preview / Delete actions. "New Page" button top-right.
  - New/Edit page via `TelerikDialog` with: title, URL slug (auto-lowercased), summary HTML field, sort order, parent page dropdown, Is Public / Is Published checkboxes
  - Duplicate URL slug guard, self-parent guard

  - "Preview" button → opens `TelerikWindow` rendering full page HTML + all active sections
  - Delete confirmation dialog; children re-parented on server
- **Logos tab:** `TelerikGrid` listing logos with active badge, alt text, file ID; "Set Active" deactivates others; "Add Logo" dialog accepts upload file GUID + alt text

#### `OrgCmsPageEdit.razor` — `/organizations/{OrgId}/cms/pages/{PageId}`
Detailed page editor.

- **Page metadata card** — title, URL slug, sort order, Published/Public toggles; Save button calls PUT endpoint
- **Summary/Intro card** — `TelerikEditor` (rich text) for `PageHtml`
- **Sections card** — ordered list of sections; each row shows type badge, title, content preview snippet; ↑↓ reorder buttons (calls PUT reorder on each move); Edit/Delete per section
- "Add Section" → `TelerikDialog` with type selector (`TelerikDropDownList`), title, IsActive, then type-specific editor via `CmsSectionEditor` component
- **Inline live preview** — toggle button splits view 50/50; right column re-renders immediately as content changes (uses `@((MarkupString)html)` for rich text sections)

#### `CmsSectionEditor.razor` — (component, no route)

| Section type | Editor |
|---|---|
| `RichText` / `CustomHtml` | `TelerikEditor` → serialises to `{ "html": "..." }` |
| `ImageBanner` | `TelerikTextBox` fields for `uploadFileId`, `altText`, `linkUrl` |
| `ContactInfo` | `TelerikCheckBox` toggles for `showAddresses`, `showEmails`, `showPhones`, `showLinks` |
| `FileGallery` / `MemberRoster` | Raw JSON textarea with format hint (enhanced in later phase) |

ContentJson is parsed on load (`JsonDocument`) and serialised on change (`JsonSerializer`). Uses `@bind-ContentJson` with `EventCallback<string>`.
