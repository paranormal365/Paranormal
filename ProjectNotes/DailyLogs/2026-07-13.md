### Theme Switcher Rewrite

The original `ThemeChanger.razor` used `ProtectedLocalStorage` (ASP.NET Data Protection), which encrypts with server-side keys that regenerate on each dev restart — causing `CryptographicException` every time the app restarted. It also had no OS preference support and caused a flash of the wrong theme on load.

**Complete rewrite:**

**`wwwroot/js/themeSwitcher.js`** — replaced `changeTheme()` with a proper module:
- `getPreferredTheme()` — resolves: saved localStorage → OS `prefers-color-scheme` → `'light'`
- `applyTheme(name)` — swaps `link.href` in-place (no remove/re-add = no flash); sets `data-bs-theme` on `<html>`
- `setTheme(name)` — persists to `localStorage` then calls `applyTheme()`
- `initTheme()` — called by Blazor on first render; applies and returns resolved theme name

**`Components/App.razor`** — added inline `<script>` block immediately after the `<link id="theme-link">`:
- Runs synchronously in `<head>` before any CSS paints (no FOUC)
- Reads `localStorage['ben-theme']`, falls back to `prefers-color-scheme`, then `'light'`
- Updates `link.href` in place and sets `html[data-bs-theme]`

**`Components/Layout/ThemeChanger.razor`** — simplified:
- Removed `ProtectedLocalStorage` dependency entirely
- `OnAfterRenderAsync`: calls `initTheme()` via JS interop; syncs switch state to returned value
- `Toggle()`: calls `setTheme()` via JS interop; updates `ThemeColor` for the icon
- `data-bs-theme` now consistently set on `<html>` (both inline script and `applyTheme()`)

**Behaviour after rewrite:**

| Scenario | Result |
|---|---|
| First load, OS = dark, no saved pref | Inline script applies `ben-dark` before paint |
| First load, OS = light, no saved pref | Inline script applies `ben-light` before paint |
| User has saved preference | localStorage wins over OS preference |
| User toggles switch | CSS swaps in-place; preference saved; no page reload |
| App restarts | Inline script re-reads localStorage immediately |

### User Impersonation Feature

SuperAdmin can view the app exactly as any other user and return to their own account at any time.

**WebApi — `POST /api/admin/impersonate/{targetUserId}` (SuperAdmin only)**
- `ImpersonateController.cs` in `Controllers/Admin/`
- Uses `SignInManager.CreateUserPrincipalAsync` + `return SignIn(principal, BearerTokenDefaults.AuthenticationScheme)`
- Issues a real bearer token for the target user without requiring their password
- Same response format as `/login` — fully compatible with `WebApiTokenResponse`

**WebApp — `IWebApiAuthService` additions:**
- `ImpersonateAsync(Guid targetUserId, string targetUserEmail)` — saves current SuperAdmin tokens, applies target user's token, sets `IsImpersonating = true`
- `StopImpersonating()` — restores original tokens, re-parses JWT to restore `IsSuperAdmin = true`

**WebApp — `IWebApiClient` addition:**
- `ImpersonateAsync(Guid targetUserId)` — calls `POST /api/admin/impersonate/{id}`, returns `WebApiTokenResponse`

**WebApp — `MainLayout.razor` impersonation banner:**
- Amber banner shown between app bar and drawer content when `TokenStore.IsImpersonating`
- Displays `"Viewing as: email@domain"` with a **Return to SuperAdmin** button
- `MainLayout.razor.css` — added `.impersonation-banner` styles
- **Admin: Users** nav item visible only when `IsSuperAdmin && !IsImpersonating`

**WebApp — `AdminUsers.razor` (`/admin/users`):**
- SuperAdmin-only page (redirects if not SuperAdmin or if currently impersonating)
- Paged grid of all users with DisplayName, Email, Created date
- **Impersonate** button per row (blocked if selecting self)
- On success, navigates to home with impersonation active
