### 6 — `EntraClaimsTransformation` — unified Entra auth

Fixed root cause of Entra JWT + role/ID claim failures across all controllers.

**Problem:** `User.IsInRole()` and `ClaimTypes.NameIdentifier` only work reliably for local Identity bearer tokens. Entra JWTs don't carry role claims and have a non-Guid `sub`/`NameIdentifier` (MSA PUID).

**Fix:** `EntraClaimsTransformation` (`Ben.Data.WebApi/Services/`) implements `IClaimsTransformation`. After Entra JWT auth, it:
1. Reads the `oid` claim (Entra Object ID, always a Guid)
2. Looks up the linked `AppUser` via `AspNetUserLogins` (`FindByLoginAsync`)
3. Injects a supplementary `ClaimsIdentity` with `app_user_id = user.Id` and DB role claims

**Result:**
- `User.IsInRole("SuperAdmin")` works for both token types
- `[Authorize(Roles = "SuperAdmin")]` works for both token types
- All `GetCurrentUserId()` methods updated to check `app_user_id` first
- Registered as `AddTransient<IClaimsTransformation, EntraClaimsTransformation>()` in `Program.cs`
- `OrganizationController` simplified back to sync methods (no `UserManager` injection needed)

## Decisions

- Password fields use native HTML `<input type="password">` — `TelerikTextBox` has no password mode.
- `[NonAction]` override on base `Create` is cleaner than adding route prefixes — keeps REST URLs canonical.
- Org list uses `Template` column for Edit/Delete buttons (shown only when permitted) rather than disabled buttons.
- `EntraClaimsTransformation` is the correct ASP.NET Core extension point for enriching external identity tokens — avoids per-controller async DB lookups and makes auth consistent everywhere.
