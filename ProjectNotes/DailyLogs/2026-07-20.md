### 3 — Timeline repaint fix on modal open

**Root cause:** The `ready` handler was calling `ws.setOptions({ height: 'auto' })` as
a repaint trigger. This is a no-op when `height` has not changed — WaveSurfer 7 only
emits `redraw` when a visual option actually differs.

**Fix (`WaveSurferPlayer.razor.js`):**  
Changed to `ws.zoom(ws.options.minPxPerSec ?? 0)` which always fires the `'zoom'` event
that the Timeline plugin listens to for repainting. Three staggered timeouts (50 ms,
200 ms, 400 ms) ensure at least one fires after the TelerikWindow open animation
(≈ 200–300 ms).

```javascript
ws.on('ready', (duration) => {
  ;[50, 200, 400].forEach(ms =>
    setTimeout(() => {
      const inst = instances.get(containerId)
      if (inst) inst.ws.zoom(inst.ws.options.minPxPerSec ?? 0)
    }, ms)
  )
  safe(dotnetRef.invokeMethodAsync('OnWsReady', duration))
})
```

### 4 — Spectrogram expands player height

**Problem:** When the spectrogram (128 px canvas) was shown, it was inserted inside the
flex-column `.ws-player` div, compressing the waveform to fill the remaining space.
Users wanted the waveform to keep its current height and the spectrogram to add below.

**Fix (`WaveSurferPlayer.razor.js` — `toggleSpectrogram`):**

- **Enable:** saves the current `playerEl.style.height`, expands by `128 px` (capped at
  CSS `max-height`), then calls `ws.setOptions({ height: 'auto' })` so the waveform
  refills the newly larger container.
- **Disable:** restores `_savedPlayerHeight` and resets WaveSurfer height.

Waveform only shrinks when `currentHeight + 128 > maxHeight`; otherwise the player
grows and the waveform is unchanged.
