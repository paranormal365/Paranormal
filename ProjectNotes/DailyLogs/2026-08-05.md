## What Shipped

### Phase D1 — EVP Markers
- New `AudioMarker` entity/table (`AddAudioMarkers` migration): time, label, `EvpConfidenceLevel` (Possible/Probable/Confirmed), optional note.
- Full CRUD stack mirroring the existing `UploadFileRegionNote` pattern: `AudioMarkerController`, `AudioMarkerRecord`/`Create`/`UpdateAudioMarkerRequest`, `AudioMarkerProfile` mapping, `IAudioMarkerRepository`, 4-layer client wiring.
- UI in `AudioFilePreview.razor`: "EVP Markers" toolbar toggle, marker list panel (time/label/confidence/note, edit/delete), add-marker-at-current-time dialog, markers rendered as color-coded zero-width regions on the waveform (reusing the existing `AddRegionAsync` machinery).

### Phase D2 — Destructive Audio Edits
- **Architecture decision:** built server-side with NAudio (new `AudioEditor.cs`, sibling to the existing `AudioClipper`) instead of the originally-planned client-side Web Audio API + SoundTouchJS — the app had no client-side audio decode/encode pipeline at all, while the existing "Trim to region" feature already proved out server-side NAudio processing.
- New `POST /api/upload-files/{fileId}/audio-edit` endpoint (`UploadFileAudioEditController`) supporting `Cut`, `Silence`, `Normalize`, `Gain`, `Fade`, `Reverse` — each always outputs 16-bit PCM WAV and saves a new derived `UploadFile` (never mutates the source).
- New "✂ Edit" panel in `AudioFilePreview.razor`: region-based Cut/Silence (act on the last user-drawn region), whole-file Normalize/Reverse, a Gain slider, and Fade in/out fields.
- 25 new passing tests (`AudioMarkerControllerTests`, `UploadFileAudioEditControllerTests`).

### Bug fixes found during browser verification
1. **"Under Review" and "Decline" buttons threw** — `UpdatePendingRequestStatusAsync`/`DeclineClientRequestAsync` called `PostAsync`/`PutAsync<..., object>`, which tries to `ReadFromJsonAsync` a body out of the server's empty `204 No Content` response and throws a `JsonException`. Fixed by switching to `PutVoidAsync`/a new `PostVoidAsync` helper (just checks `IsSuccessStatusCode`, doesn't read a body).
2. **Decline-confirm dialog crashed with `NullReferenceException`** — `OrgPendingRequests.razor` interpolated `_declineTarget.City`/`.State` without a null-check; Telerik's window re-renders its content once more during the close transition after the field is nulled out. Fixed with `?.`.
3. **Pre-existing app-wide startup crash, unrelated to any of the above** — `Ben.Video.Editor`'s `FfmpegService`/`OPFSService` were registered `AddSingleton` despite depending on circuit-scoped `IJSRuntime`, so ASP.NET Core's DI validation refused to start the host at all. Fixed in the separate `Ben.Video.Editor` repo (`ServiceCollectionExtensions.cs`) by switching both to `AddScoped`; both also hold per-circuit state (loaded JS module ref, encode progress), so singleton was wrong on both DI-validity and correctness grounds. Updated `VideoEditorRegistrationTests` to match.

### New feature — declined request → resubmit to another org
Prompted by manually reproducing the decline bug and noticing "My Requests" never reflected it.
- Added `ClientRequestStatus.Declined`, set by `CaseController.DeclineClientRequest` when every `ClientRequestOrganization` for a request has been rejected (never fires while a second org is still pending — covered by test).
- New `POST /api/client-requests/{id}/add-organization` (`ClientRequestController`) lets the owner send a `Declined` request to one more org, subject to the existing 2-org cap, then flips the request back to `Submitted`.
- `ClientRequests.razor`: red "Declined" badge + "Choose Another Organization" button opening a picker that reuses the existing distance/area-of-operation-sorted `PublicOrganizationSearchController` search (same one the initial-submission wizard uses), filtered to exclude orgs already applied to.
- Verified live end-to-end: submit → decline → "Declined" badge appears → picker correctly shows "no other orgs" once the only in-range org has already been applied to.

## Phase D3 — Speed/Pitch, Silence Detection, Voice-Band Overlay

- Ported Stephan M. Bernsee's public-domain SMB phase-vocoder algorithm to C# (`SmbPitchShifter.cs`), used for both `Pitch` (semitone shift) and `Speed` (resample + inverse pitch-shift to preserve pitch) operations in `AudioEditor.cs`.
- Client-side silence detection and a voice-frequency-band waveform overlay added to `WaveSurferPlayer.razor.js`, reusing WaveSurfer's own decoded `AudioBuffer` (`getDecodedData()`) rather than a second decode pass.

## Phase E — Multi-Track Mixer (all four sub-steps, `feature/media-editor-phase-e`)

Branched from `feature/media-editor-phase-d3` (not bare `develop`) so it carries all of Phase D.

- **E1 — Files/Evidence tab:** new `CaseFile` entity/table linking a case to any `UploadFile` (any content type, not audio-only — a deliberate scope expansion over the original mixer-only plan, since no general case file list existed yet). `CaseFileController` (list/upload/delete, delete un-links but never deletes the underlying `UploadFile` — chain of custody), new "Files" tab in `CaseDetail.razor`.
- **E2 — Mixer page shell:** `CaseAudioMixPage.razor` at `/organizations/{orgId}/cases/{caseId}/audio-mix`, gated by the same org-member check as every other case sub-page. 8-track grid, time ruler, transport bar (Play/Pause/Stop left disabled — no live preview yet, out of scope).
- **E3 — Placement & controls:** click "Add" on a clip to place it on the first empty track at offset 0; drag a placed block left/right to reposition (plain pointer events in a new `CaseAudioMixPage.razor.js`, same JS-isolation pattern as `WaveSurferPlayer.razor.js` — only the final offset is reported back to Blazor, no per-pixel SignalR chatter). Mute/Solo/Volume/Pan are live per-track state.
- **E4 — Export:** `AudioMixer.cs` (server-side NAudio, same house style as `AudioEditor.cs`) downmixes each track to mono, resamples to a common rate, applies gain (dB)/constant-power pan/mute/solo, sums at each clip's offset, and soft-clips via `tanh` to avoid harsh digital clipping when tracks sum past unity. `CaseAudioMixController` exposes `POST .../audio-mix/export`, validates every clip belongs to the case and is audio, and saves the mixdown as a new "Audio Mix" `UploadFile` (new seeded file type, fixed GUID `40000000-...-000000000001`) linked via `CaseFile`.
- 18 new tests (`AudioMixerTests` — offset placement, pan, gain correctness via sine tones; `CaseAudioMixControllerTests` — permission/validation/persistence).
- Browser-verified: logged in as `haveben@msn.com`, confirmed the Files tab and Audio Mixer page both render correctly end-to-end from Organizations → Cases → case detail (permission gate, empty states, 8-track grid, correctly-disabled Export button). File upload itself isn't automatable through the current browser tooling (no OS file-picker support), so the upload→clip→export path is verified via the controller test suite rather than a live click-through.
- One non-code snag: the running dev server predated the new `CaseAudioMixPage.razor.js` static asset and 404'd on it until restarted — not a bug, just a stale process.
