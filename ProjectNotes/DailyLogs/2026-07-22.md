### 2. Shadow DOM Fix — Region Creation After Zoom (branch commit 1)

**Root cause:** WaveSurfer 7 attaches a shadow root to a wrapper div it creates inside the container.
`container.querySelector('[part="scroll"]')` returned `null` because the scroll element is inside
`child.shadowRoot`, not directly in `container`.

- Added `_wsScrollEl(container)` helper that iterates `container.children`, checks `child.shadowRoot`,
  then queries inside the shadow root for `[part="scroll"]`
- Updated `_wsTimeAtClientX(ws, container, clientX)` to use `_wsScrollEl`; formula mirrors WaveSurfer's
  own seek logic: `(scrollLeft + clientX - scrollEl.left) / scrollWidth * duration`
- Both `onPointerDown` and `onPointerUp` in the drag-to-create code now use `_wsTimeAtClientX`,
  so region start/end times are correct at any horizontal zoom level

### 3. Async Worker Spectrogram Viewport Rendering (branch commit 1 continued)

**Problem:** `_drawSpectrogram` did O(nFrames × nBins) `fillRect` calls — ~13M for a 5-min file at
512 fftSamples. Called synchronously on every zoom/scroll event → jank.

**Architecture:**

- **`_drawSpectrogram` rewrite**: now O(W × H) pixel-buffer approach — one `putImageData` call instead
  of millions of `fillRect` calls. Orders of magnitude faster. `_drawSpectrogramLabels` extracted.
- **`spectrogram-draw-worker.js`** (new): Web Worker at `/js/wavesurfer/spectrogram-draw-worker.js`.
  Receives `{ flat: Float32Array, nFrames, nBins, width, height, version, cacheKey }` (transferred);
  returns `{ pixels: Uint8ClampedArray, width, height, version, cacheKey }` (transferred). O(W × H).
- **`_redrawSpectrogramViewport`** rewritten with two paths:
  - *Fast path*: GPU-accelerated `ctx.drawImage(prerenderCanvas, ...)` ~1 ms, synchronous (once pre-render ready)
  - *Slow path*: 30-entry `ImageData` cache + persistent draw Worker + version counter for stale discard
- **`_scheduleSpectrogramRedraw(containerId, debounce)`**: zoom = immediate; scroll = 60 ms debounced (silent)
- **Scroll/zoom listeners**: check `_prerenderCanvas` first — instant drawImage if available, else debounced Worker

### 4. Pre-Render OffscreenCanvas (branch commit 2)

After FFT completes, `_startSpectrogramPrerender(containerId)` starts a background Worker rendering the
**entire file** at `min(8192, max(2048, nFrames)) × 128` pixels (~30 ms). Once the `OffscreenCanvas` is
ready, **all** viewport operations (zoom, scroll, playback auto-scroll) become a single `drawImage` crop:

```
ctx.drawImage(prerenderCanvas, srcX, 0, srcWidth, 128, 0, 0, canvasW, 128)
```

- ~1 ms, GPU-accelerated, synchronous — no Worker overhead for any normal zoom level
- Pre-render width ≈ 1 px per FFT frame for common `fftSamples` values (≤ 4096)
- **Spectrogram now follows the audio playhead smoothly during playback** — no debounce needed
- Blurs slightly at extreme zoom (> 32×) — acceptable (whisper detection typically 2–8×)
- Cleanup in `toggleSpectrogram(disable)`, `setSpectrogramResolution`, `destroy()`
- Frequency labels drawn fresh on top via `_drawSpectrogramLabels` after each drawImage

### 5. Loading Text Stuck + Labels Hidden by Default (branch commit 3)

Two targeted fixes:

- **Loading text stuck during playback**: `_scheduleSpectrogramRedraw` scroll path was calling
  `_showSpectrogramRecalculating` immediately on every scroll event. WaveSurfer playback auto-scroll fires
  continuously; the 60 ms debounce timer kept getting cancelled so `_hideSpectrogramLoading` never fired.
  Fix: removed `_showSpectrogramRecalculating` from scroll debounce path — scroll redraws are now silent.
- **Frequency labels hidden by default**: `_spectrogramLabels` defaulted to `false`. Changed to `true`
  so Hz/kHz labels are visible immediately when the spectrogram opens.

### 6. Region Playback Stops at Region End (branch commit 4)

**Root cause:** `ws.seekTo(region.start / duration)` sets `media.currentTime`, which queues a
`seeking` event asynchronously on the audio element. By the time it fires, `ws.on('seeking', stopAndClean)`
was already registered, so `stopAndClean()` immediately removed the `timeupdate` monitor. With no
monitor active, playback ran past the region end.

**Fix:** added `let skipNextSeek = true` flag. The first `seeking` event (from our own `seekTo`) is
silently consumed. All subsequent user-initiated seeks still trigger `stopAndClean()`.

## Key Architectural Notes

### Spectrogram Two-Tier Rendering

```
Tier 1 — Pre-render OffscreenCanvas (fast path)
  After FFT: Worker renders full file → OffscreenCanvas stored on instance
  Viewport changes: ctx.drawImage(prerenderCanvas, srcX, 0, srcW, 128, 0, 0, canvasW, 128)
  ~1 ms, GPU, synchronous, no debounce → smooth playback tracking

Tier 2 — Slice render Worker (slow path / fallback)
  Used for ~30 ms window before pre-render is ready
  30-entry ImageData cache keyed by startFrame:endFrame:canvasW:showLabels
  Version counter prevents stale results from overwriting newer renders
```

### Shadow DOM Traversal

WaveSurfer 7 creates `div.attachShadow({mode:'open'})` for its internal layout.
`container.querySelector('[part="scroll"]')` always returns `null` (does not pierce shadow DOM).
Must use: `child.shadowRoot.querySelector('[part="scroll"]')` where `child` is the first child
of the outer container that has a `shadowRoot`.

### Region Playback Fix Pattern

`ws.seekTo()` fires `seeking` asynchronously after the JS call stack clears.
Always skip one `seeking` event after a programmatic seek-to-start to avoid
tearing down monitoring listeners before playback reaches the target region end.
