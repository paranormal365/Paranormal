## Root Causes Found & Fixed

### 1 — `WebApiBearerTokenHandler` DI scope bug (root of all auth failures)

**Problem:** `IHttpClientFactory` resolves `DelegatingHandler` instances from the **root DI scope**, not the Blazor circuit scope. Every `WebApiBearerTokenHandler` therefore received a fresh, empty `IWebApiTokenStore` — unrelated to the circuit's actual token store. Bearer tokens were never sent to the WebApi. All authenticated calls silently returned `null`.

**Fix:** Removed `WebApiBearerTokenHandler` from the `IWebApiClient` pipeline. Moved auth header injection into `WebApiClient` directly (constructor-injected `IWebApiTokenStore` + `Auth()` private helper that reads the token at request time).

Files: `Ben.Web.WebApp/Services/WebApi/WebApiClient.cs`, `Ben.Web.WebApp/Program.cs`

---

### 2 — `MeController` crash on MSA tokens (`FormatException`)

**Problem:** Personal Microsoft accounts (MSA) issue JWT tokens whose `sub` claim is a base64-like string, not a GUID. `UserManager.GetUserAsync(User)` internally calls `UserStoreBase.ConvertIdFromString(sub)` → `new Guid(sub)` → `FormatException`. This crashed `/api/me` with 500 before it could return `Guid.Empty`.

**Fix:** Wrapped `GetUserAsync(User)` in `try-catch(FormatException)`. On catch, falls through to Step 3 (`return Guid.Empty`), which triggers the `/entra/complete-profile` redirect.

File: `Ben.Data.WebApi/Controllers/MeController.cs`

---

### 3 — JwtBearer audience mismatch for MSA tokens

**Problem:** WebApi JwtBearer configured with `jwt.Audience = "api://e75f71ef..."`. MSA tokens (personal Microsoft accounts) set `aud = "e75f71ef..."` (plain GUID), not `"api://e75f71ef..."`. Token validation failed with 401.

**Fix:** Replaced `jwt.Audience` with `TokenValidationParameters.ValidAudiences = new[] { "api://clientId", "clientId" }` to accept both formats.

File: `Ben.Data.WebApi/Program.cs`

---

### 4 — `TryBridgeEntraAuthAsync` could override local login / leave partial auth state

**Problems:**
- No guard against running when user already has a `UserId` (could override a completed local login)
- On `Guid.Empty` (unlinked Entra user), set partial state (`AccessToken`, `UserEmail`) before clearing it — left stale state visible in UI
- On API failure (`me == null`), never cleared partial state → user appeared partially signed in with just an email

**Fix:**
- Added early `return` if `TokenStore.UserId.HasValue`
- Re-checked `UserId.HasValue` after the `await` (race condition guard)
- On `Guid.Empty`: clears `AccessToken`, `UserEmail`, `IsEntraSession` before navigating to `/entra/complete-profile`
- On `null` (API failure): clears partial state and returns (no phantom auth)

File: `Ben.Web.WebApp/Components/Layout/MainLayout.razor`

---

### 5 — `Login.razor` false redirect from partial Entra state

**Problem:** `OnInitialized` redirected to `/` when `TokenStore.IsAuthenticated` was true. `IsAuthenticated` is `!string.IsNullOrWhiteSpace(AccessToken)` — which was true even during a partial Entra bridge (token set, but `UserId` not yet resolved). Users couldn't reach the login form while an Entra session was active.

**Fix:** Changed redirect condition from `IsAuthenticated` to `IsAuthenticated && UserId.HasValue`.

File: `Ben.Web.WebApp/Components/Pages/Login.razor`
