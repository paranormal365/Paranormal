## NEW SESSION: Ben.Service.Security Integration (2026-07-12 Afternoon)

### Issue: Namespace and Entity Conflicts

When integrating `Ben.Service.Security` into `Ben.Data.WebApi`, the build encountered multiple conflicts:

1. **Enum Conflicts**
   - `Ben.Data.Common.Enums.OrganizationSecurityAction` (Read=1, Create=2, Update=3, Delete=4)
   - `Ben.Service.Security.Enums.OrganizationSecurityAction` (Create=1, Read=2, Update=4, Delete=8, All=15 — flags enum)
   - `Ben.Data.Common.Enums.OrganizationSecurityTable` vs `Ben.Service.Security.Enums.OrganizationSecurityTable`

2. **Service Interface Conflicts**
   - `Ben.Service.RepositoryService.GenericInterfaces.IOrganizationSecurityService` (legacy, with HasAccessAsync, SearchUsersAsync)
   - `Ben.Service.Security.Services.IOrganizationSecurityService` (new, with HasPermissionAsync, AddMemberAsync, etc.)

3. **Entity Model Conflicts**
   - `Ben.Service.Security.Models.OrganizationAccessGrant` (DTO with UserId, Table, Actions flags)
   - `Ben.Data.Source.Entities.OrganizationAccessGrant` (EF entity with AppUserId, TableName, ActionName, IsAllowed boolean)

### Resolution Strategy

**Namespace Management:**
- Added `Ben.Service.Security` project reference to `Ben.Data.WebApi.csproj`
- Updated `GlobalUsings.cs` to NOT import conflicting enum/entity namespaces
- Used fully qualified name in `Program.cs`:
  ```csharp
  builder.Services.AddScoped<Ben.Service.Security.Services.IOrganizationSecurityService, 
                               Ben.Service.Security.Services.OrganizationSecurityService>();
  ```
- Left `Ben.Service.RepositoryService.GenericInterfaces.IOrganizationSecurityService` intact (used by existing controllers)

**Entity Mapping (Adapter Pattern):**
- `Ben.Service.Security.Models` are DTOs, NOT EF entities
- `OrganizationSecurityService` uses `Ben.Data.Source.Entities` for database operations
- Created using aliases for disambiguation:
  ```csharp
  using DataAccessGrant = Ben.Data.Source.Entities.OrganizationAccessGrant;
  using DataMembership = Ben.Data.Source.Entities.OrganizationUserMembership;
  using DataCommonAction = Ben.Data.Common.Enums.OrganizationSecurityAction;
  using DataCommonTable = Ben.Data.Common.Enums.OrganizationSecurityTable;
  ```

### Service Implementation Adaptations

Updated `OrganizationSecurityService.cs` to bridge the model gap:

**Property Mapping:**
| Service Layer | Database Entity | Conversion |
|---|---|---|
| `UserId` | `AppUserId` | Direct |
| `Table` (Flags enum) | `TableName` (Common enum) | Cast with enum conversion |
| `Actions` (Flags enum: 1,2,4,8) | `ActionName` + `IsAllowed` bool | Map flags to common enum, check IsAllowed |
| `Role` enum (Owner/Admin/Manager/Member/Viewer) | `IsOrganizationAdmin` bool + `IsActive` | Owner if IsOrganizationAdmin, else Member |
| `RemovalDate` | `IsActive` bool | null → true, datetime → false |

**Service Methods Adapted:**
- `HasPermissionAsync()`: Casts enums, queries with `IsAllowed` flag check
- `IsMemberAsync()`: Checks `IsActive` instead of null `RemovalDate`
- `GetUserOrganizationsAsync()`: Filters by `IsActive` 
- `GetUserRoleAsync()`: Maps `IsOrganizationAdmin` → Owner/Member
- `AddMemberAsync()`: Sets `IsActive = true`, `IsOrganizationAdmin` based on role
- `RemoveMemberAsync()`: Sets `IsActive = false`
- `GrantAccessAsync()`: Creates/updates grant with `IsAllowed = true`
- `RevokeAccessAsync()`: Sets `IsAllowed = false`

## Architecture Notes

### Current Design (Interim)

The implementation uses an **adapter pattern** where:
1. `Ben.Service.Security` provides the conceptual two-level security model (roles, flags permissions)
2. `Ben.Data.Source.Entities` maps to existing database schema (booleans, action names)
3. `OrganizationSecurityService` bridges them with conversion logic

This allows the new security framework to work with existing data while maintaining clean architecture.

### Future Enhancements

**To fully realize Ben.Service.Security's design without mapping overhead:**

   - Deprecate `IsOrganizationAdmin` in favor of proper role enum

   - Replace `ActionName` + `IsAllowed` with single `Actions` int field
   - Migration strategy: Set Actions = corresponding flag value when IsAllowed = true
