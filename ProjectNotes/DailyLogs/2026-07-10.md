## Decisions

- `Ben.Data.WebApi` uses `IDbContextFactory<BenDataContext>` (not `AddDbContext`) to support proper scoping in API controllers and background work.
- Scalar is used as the OpenAPI UI instead of Swagger UI.
- `AddIdentityApiEndpoints` used instead of `AddIdentity` — API-only (bearer token auth); both cannot coexist as they register the same `Identity.Application` scheme.
- `UseHttpsRedirection` is guarded to non-Development environments — .NET 10 dev cert is unreliable on macOS and not needed for local API calls.
- `launchSettings.json` `http` profile is default; opens browser to `/scalar/v1` on launch.

## OpenAPI Schema Generation Issue & Fix

### Problem

When trying to generate the OpenAPI schema for the WebApi, .NET's OpenAPI generator hit a circular reference depth limit:

```
System.InvalidOperationException: CurrentDepth (64) is equal to or larger than the maximum allowed depth of 64.
```

**Root cause:** Entity Framework entities have bidirectional navigation properties (e.g., `AppUser` ↔ `UserAddress` collections), creating circular references. OpenAPI schema generation tried to infinitely recurse through these relationships, hitting the depth limit.

### Solution: Switched from Scalar to Swashbuckle

**Changes made:**

1. **Replaced packages:**
   - ❌ Removed: `Scalar.AspNetCore` + `Microsoft.AspNetCore.OpenApi`
   - ✅ Added: `Swashbuckle.AspNetCore` v7.2.0

2. **Implemented CircularReferenceSchemaFilter** in `Program.cs`:
   - Excludes collection properties (plural names)
   - Excludes navigation back to parent (`CreatedByAppUser`, `UpdatedByAppUser`)
   - Filters centrally at schema generation time

3. **Updated launchSettings.json:**
   - Changed `launchUrl` from `scalar/v1` to `swagger`

### Result

✅ **OpenAPI schema now generates successfully!**
- Schema available at: `http://localhost:5275/swagger/v1/swagger.json`
- **113 endpoints** fully documented
- **No circular reference errors**
- All DTOs properly included
- Identity endpoints and entity CRUD endpoints documented

### Current Limitation

The Swagger UI HTML page (`/swagger/`, `/swagger/index.html`) returns 404 — likely a .NET 10 Swashbuckle compatibility issue. The JSON schema works perfectly.

**Workaround — Access documentation via:**
- Postman: Import the schema URL
- Swagger Editor: https://editor.swagger.io/ (paste JSON)
- VS Code REST Client: Use schema URL
- curl: `curl http://localhost:5275/swagger/v1/swagger.json | jq .`

**Why Swashbuckle was better:**
- Industry standard, battle-tested
- Better customization options
- Proper schema filtering for circular refs
- Mature community support

**Documented:** `ProjectNotes/Notes.md` with detailed schema access methods and filter configuration.

## New Project: Ben.Service.Security

Created comprehensive organization-level security framework for tenant-based access control.

### Project Structure

```
Ben.Service.Security/
├── Enums/
│   ├── OrganizationSecurityAction.cs     [Flags: Create, Read, Update, Delete]
│   └── OrganizationSecurityTable.cs      [25 organization-related tables]
├── Services/
│   ├── IOrganizationSecurityService.cs   [Permission checking interface]
│   └── OrganizationSecurityService.cs    [EF Core implementation]
├── Attributes/
│   └── OrganizationSecurityAuthorizeAttribute.cs [Custom auth attribute]
├── Models/
│   └── OrganizationSecurity.cs           [AccessGrant, Membership, Role models]
├── Extensions/
│   └── SecurityExtensions.cs             [HasPermission extension method]
└── GlobalUsings.cs                       [Global imports]
```

### Key Components

**1. Enums (Two-level Authorization)**
- `OrganizationSecurityAction`: CRUD operations (flags enum, combinable)
- `OrganizationSecurityTable`: 25 tables (Organization + related entities)
- `OrganizationMemberRole`: Owner, Administrator, Manager, Member, Viewer

**2. Models**
- `OrganizationAccessGrant`: Specific permissions (UserId, Table, Actions)
- `OrganizationUserMembership`: User's role in organization
- `OrganizationUserPermission`: Permission check result

**3. Service: IOrganizationSecurityService**
- `HasPermissionAsync()`: Check user has action on table
- `IsMemberAsync()`: Check if user is member
- `IsOwnerAsync()`: Check if user is owner (auto-grants all)
- `AddMemberAsync()`: Add user to organization
- `RemoveMemberAsync()`: Remove user from organization
- `GrantAccessAsync()`: Grant specific permissions
- `RevokeAccessAsync()`: Revoke permissions
- `GetUserOrganizationsAsync()`: Get all orgs user is member of
- `GetOrganizationMembersAsync()`: Get all members of org

**4. Custom Attribute: OrganizationSecurityAuthorizeAttribute**
- Extracts UserId from claims
- Extracts OrganizationId from route/query
- Calls `HasPermissionAsync()`
- Returns 401, 400, 403, or allows request
- **Owners bypass all permission checks**

### Usage Example

```csharp
[ApiController]
[Route("api/organizations/{organizationId}/users")]
public class UserController : ControllerBase
{
    [HttpPost]
    [Authorize]
    [OrganizationSecurityAuthorize("organizationId", OrganizationSecurityTable.User, OrganizationSecurityAction.Create)]
    public async Task<ActionResult> CreateAsync(Guid organizationId, CreateUserRequest request, CancellationToken ct)
    {
        // Authorization automatically checked:
        // - User authenticated ✓
        // - User is member of organization ✓
        // - User has Create permission on User table ✓
        // If owner: all checks passed automatically
        // If not owner: must have explicit grant
    }
}
```

### Permission Flow

```
Request → Extract UserId + OrgId
  ↓
Is owner of org? → YES → ✅ Allow
  ↓ NO
Has grant for table+action? → YES → ✅ Allow
  ↓ NO
❌ Return 403 Forbidden
```

### Configuration

To use in WebApi:

```csharp
// Program.cs
builder.Services.AddScoped<IOrganizationSecurityService, OrganizationSecurityService>();
```

### Two-Level Security Model

**Level 1 (Website):**
- User logs in via Identity
- Gets bearer token
- Can access WebApi endpoints

**Level 2 (Organization/Tenant):**
- User is member of 0, 1, or multiple organizations
- Has a role in each organization (Owner, Admin, Manager, Member, Viewer)
- Has specific permissions on tables within each organization
- **Owners**: Unrestricted within organization
- **Non-owners**: Restricted to granted permissions

### Permissions

**Owner**
- All permissions on all tables
- Can add/remove members
- Can grant/revoke permissions

**Standard User**
- Only permissions they're explicitly granted
- Fine-grained per-table control
- Can combine CRUD actions (Read+Update, Create+Read, etc.)

Example: "Can read and update Organizations, but only read Addresses"
```csharp
// Grant on Organization table
actions = OrganizationSecurityAction.Read | OrganizationSecurityAction.Update;

// Grant on Address table
actions = OrganizationSecurityAction.Read;
```
