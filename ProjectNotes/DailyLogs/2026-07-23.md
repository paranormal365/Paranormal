## Items Completed

### 1. Option B — Remove Write Methods from `IRepositoryBase` / `RepositoryBase`

**Problem:** `Create`, `Update`, and `Delete` in `RepositoryBase<T>` created a new `DbContext`, staged changes, then immediately disposed without calling `SaveChanges`. Nothing was ever persisted. Additionally, `IRepositoryManager.SaveChangesAsync` threw `NotImplementedException`. Both were silent, broken dead code.

**Resolution (Option B — explicit read-only repositories):**
- Removed `Create`, `Update`, `Delete` from `IRepositoryBase<T>` and `RepositoryBase<T>`
- Removed the private `GetById(BenDataContext, Guid)` helper that was only used by `Delete`
- Removed `SaveChangesAsync` from `IRepositoryManager` and `RepositoryManager`
- Repositories are now explicitly read-only; all write operations live in controllers via `IDbContextFactory<BenDataContext>` — which was already 100% of actual usage
- Removed the `SaveChangesAsync_Throws_NotImplemented` test that was asserting the broken behaviour

### 2. Geocoding — Move from Dead Repository Overrides to Admin Controllers

**Problem:** `OrganizationAddressRepository` and `UserAddressRepository` overrode `Create` and `Update` to apply geocoding, then called `base.Create/Update`. Since base never saved, geocoding never executed.

**`AddressGeocodingService` changes:**
- Changed from `internal static` → `public static` so WebApi can reference it
- `GeocodingLookupResult` changed from `internal sealed record` → `public sealed record`
- Replaced blocking `TryResolveCoordinates` (used `GetAwaiter().GetResult()`) with fully async `TryResolveCoordinatesAsync(string, string?, string, string, string, string, CancellationToken)`
  — uses `await HttpClient.GetAsync(url, cancellationToken)` and `await response.Content.ReadAsStringAsync(cancellationToken)` throughout

**`AdminOrganizationAddressController` and `AdminUserAddressController`:**
- Override `Create` and `Update` from `AdminEntityControllerBase`
- Each override calls `await ApplyGeocodingAsync(entity, cancellationToken)` before delegating to `base`
- Private static `ApplyGeocodingAsync` populates `Latitude`, `Longitude`, `GeocodingResponseJson`, `GeocodingResultType` on the entity

**Dead overrides in repositories:**
- Removed `Create`/`Update` from `OrganizationAddressRepository` and `UserAddressRepository`
- Left `// NOTE` comments in each file documenting where geocoding now lives

### 3. Bug Fix — `RepositoryBase.FindListAsync(predicate, includes[], ...)` Missing Where Clause

**Problem:** The `FindListAsync(Expression<Func<T, bool>> expressionPredicate, Expression<Func<T, object>>[]? includes, bool trackChanges, CancellationToken)` overload applied includes but never called `.Where(expressionPredicate)` — it returned all rows regardless of predicate.

**Fix:** Added `query = query.Where(expressionPredicate)` after `ApplyIncludes`. The bug was caught by the new `RepositoryReadPathTests` suite.

### 8. Named Organization Role System (from Organization Security.md — gaps D + E)

**Problem:** The spec described a role-based permission system where org owners/admins create named roles with per-section CRUD flags, assign members to multiple roles, and permissions resolve via OR logic. The codebase only had direct per-user `OrganizationAccessGrant` rows and a fixed `OrganizationMemberRole` enum.

**Implementation:**

**New entities (3):**
- `OrganizationRole` — named role scoped to an organization (Name, Description, IsActive, SortOrder, audit fields)
- `OrganizationRolePermission` — per-table CRUD bitmask (`OrganizationSecurityTable` + `OrganizationSecurityAction`) for a role; unique index per (roleId, tableName)
- `OrganizationRoleMembership` — links an `OrganizationUserMembership` to a named role; unique index per (roleId, membershipId)

**EF migration:** `AddOrganizationNamedRoles`

**Repository layer:** 3 new interfaces + implementations wired into `OrganizationRepositoryManager`

**Security service:** `HasAccessAsync` updated — after checking direct grants, now also queries named role permissions via OR logic (any active role the user belongs to that has matching table+action → true)

**Service models + mappings:** `OrganizationRoleRecord`, `OrganizationRolePermissionRecord`, `OrganizationRoleMembershipRecord` + AutoMapper profiles

**WebApi:** `OrganizationRoleController` at `api/organizations/{orgId}/roles` — 10 endpoints covering role CRUD, replace-all permissions (`PUT .../permissions`), and member assignment

**Blazor (`Ben.Web.Library/Organization/Roles/`):**
- `OrgRolesManager.razor` — grid of roles with create/edit/delete; takes `OrgId` parameter
- `OrgRoleEditor.razor` — role details form + 16-section hierarchical CRUD permission toggles (sub-sections indented with `ms-4`) + member assignment grid
- `OrganizationView.razor` converted to `TelerikTabStrip` — "Details" tab (existing) + "Roles" tab (new); Roles tab visible to SuperAdmin and org Owner/Administrator

**`IBenAdminClient` + `BenAdminClient`:** 10 new org-role API methods
