## Microsoft Identity Status (Verified)

- `Ben.Data.WebApi` is configured to use Microsoft Identity via API endpoints.

### How It Is Implemented

- Service registration in `Program.cs`:
  - `AddIdentityApiEndpoints<AppUser>(...)` configures Identity for API-based auth.
  - Password policy is explicitly configured:
    - Require digit
    - Min length 8
    - Require uppercase
    - Require lowercase
    - Non-alphanumeric not required
    - Unique email required
  - `.AddEntityFrameworkStores<BenDataContext>()` wires Identity persistence to EF Core.
  - `.AddDefaultTokenProviders()` enables standard token generation flows.
- Endpoint mapping in `Program.cs`:
  - `app.MapIdentityApi<AppUser>()` exposes built-in Identity API routes.
- Middleware in `Program.cs`:
  - `app.UseAuthentication()` and `app.UseAuthorization()` are in the request pipeline.
- Data store implementation:
  - `BenDataContext` inherits `IdentityDbContext<AppUser, IdentityRole<Guid>, Guid>` in generated context code.
  - `OnModelCreating` calls `base.OnModelCreating(modelBuilder)` so standard Identity schema configuration is applied.

### Practical Result

- WebApi is Identity-enabled for API authentication and user management against the SQL-backed `BenDataContext` store.

## Tenant Security Model and Organization Registration (Completed)

### Objective

- Implement tenant-aware authorization where:
  - `SuperAdmin` can access all organizations.
  - Non-superadmin users can belong to none, one, or many organizations.
  - Organization admins can manage users and grants only within their organization.
  - Users can register one or more organizations they own.
  - Security checks can be performed with: `OrganizationId + TableEnum + ActionEnum`.

### Data Model Added

- New entity: `OrganizationUserMembership`
  - Links `AppUser` to `Organization`
  - Flags: `IsOrganizationAdmin`, `IsActive`
  - Audit fields (`DateCreated`, `CreatedByAppUserId`, etc.)
- New entity: `OrganizationAccessGrant`
  - Scoped by `OrganizationId`, `AppUserId`
  - Permission key: `TableName` + `ActionName`
  - Decision field: `IsAllowed`

### Enums Added (Common Contract)

- `OrganizationSecurityTable` (covers current main entities)
- `OrganizationSecurityAction`
  - `Read`
  - `Create`
  - `Update`
  - `Delete`

### Service Layer Added

- New interface: `IOrganizationSecurityService`
- New implementation: `OrganizationSecurityService`

Key behavior:
- `HasAccessAsync(...)`
  - immediate allow for users in `SuperAdmin` role
  - otherwise requires active org membership
  - org admins are allowed for all actions/tables in their org
  - non-admin members require explicit allowed grant in `OrganizationAccessGrant`
- `GetOrganizationsForUserAsync(...)`
  - `SuperAdmin`: returns all organizations
  - non-superadmin: returns active memberships only
- `RegisterOrganizationAsync(...)`
  - allows authenticated user to create a new organization
  - auto-creates membership as active org admin for creator
- `GetOrganizationUsersAsync(...)`, `UpsertMembershipAsync(...)`, `SetAccessGrantAsync(...)`
  - manageable by org admin of that tenant or superadmin

### WebApi Endpoints Added

#### Organization Security (per organization)

Route base:
- `api/organizations/{organizationId}/security`

Endpoints:
- `GET my-access?table=...&action=...`
- `POST check-access`
- `GET users`
- `PUT users/{targetUserId}/membership`
- `PUT users/{targetUserId}/grants`

#### Organization Membership / Self-Registration

Route base:
- `api/security/organizations`

Endpoints:
- `GET mine`
  - returns all organizations the current user belongs to
  - for superadmin, returns all organizations
- `POST register`
  - registers a new organization for current user
  - creator becomes active organization admin
